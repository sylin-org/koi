# Public claim contract

A public claim names an actual artifact and supported scenario. Use the
[readiness page](../../docs/launch/README.md) as the single artifact/channel record.

| Claim | Required evidence | Current wording boundary |
| --- | --- | --- |
| Container-to-LAN discovery/lifecycle | Actual Windows/Linux peer application and restart/removal receipt | Describe implemented components; call the focused preview a target until accepted |
| Stable client-resolvable name | Normal independent-client resolver and actual application request | A direct Koi lookup alone is insufficient |
| Trusted service URL | Exact SAN, client root/DNS setup, normal TLS validation and renewal | Public grant/listener workflow remains incomplete until trusted-extension proof |
| Works with Caddy/Traefik/resolver | Complete recipe with exact versions, hooks, grant and recovery | Format compatibility is not a tested integration |
| Installable channel | Independent public registry/download and quickstart | npm/OS packaging source is prepared until its public channel works |
| Platform support | Named artifact plus appropriate build/native case | An available binary is not proof of every runtime/client workflow |
| Traction | Independent activated and retained operators with denominator | Downloads, fleet agents and maintainer use do not establish retention |
| Security | Exact documented threat model and relevant verification | No universal client trust, fine-grained principal scopes or CRL/OCSP claim |

Avoid “unique”, “everything just works”, universal zero-configuration statements
and measured time-to-value claims without comparative or user evidence.
Preserve clear limits while explaining the useful task.
