# Release and communication plan

1. Complete the bounded operator-preview gate in
   [Epic 004](../../fleet/epics/004-container-lan-adoption.md), with formative
   observation during implementation.
2. Prepare exact versioned install instructions, proof, limits, verification,
   upgrade/recovery information and a reproducible container demo.
3. Publish the selected artifact through the existing release contract; verify
   public downloads and the quickstart independently before calling a channel available.
4. Use one suitable operator or integration-maintainer channel for a specific
   task demonstration. Check current channel rules when preparing the actual post.
5. Follow operator outcomes and support capacity before increasing reach.
6. Publish the trusted-service extension only with its own complete proof,
   or explicitly defer it if retained-use evidence supports a narrower product.

Repository metadata, owned-page copy and release notes should describe the same
tested scope. The preview does not wait for whole-desktop completion.
Community/individual messages require explicit communication authorization and
reviewable content. This plan does not send or schedule anything.
