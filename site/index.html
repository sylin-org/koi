KOI

Container services that belong on your LAN.

Publish a container service, find its endpoint from another machine, and keep names and discovery state in step with its lifecycle.

Koi is open source for container/LAN developers and capable homelab operators, especially on Windows and Linux. It runs on the host without an account or hosted control plane, alongside your existing container engine and networking tools.

Certmesh also provides identity and trust for your private space: a group of machines and participating applications using a local authority you control.

Start with one real application

  1. Choose a release and follow its installation guide.
  2. Opt a container in with koi.announce and a published host port.
  3. Discover its endpoint from a second machine and open the actual application.
  4. Stop, restart and recreate it; verify the application and derived state again.

The label is the beginning

docker run -d --name koi-demo -p 8080:80 \
  --label koi.announce=koi-demo nginx:alpine

A reachable engine and a running host daemon are prerequisites. This is a sample app. Use a free host port. A discovery record does not prove application readiness or configure another machine's DNS.

Private-space identity and trust

Certmesh gives members of your private space a certificate issued by your own local certificate authority. It supports member enrollment and certificate renewal, so a participating application can check a peer's identity instead of relying only on its advertised name or IP address.

Koi-aware applications can consume signed membership and revocation information to check which peers remain members. Encrypted backups, restore and manual promotion provide recovery options when a CA host needs replacing.

Network access rules and each application's authorization policy remain separate. Browser HTTPS also needs a matching service certificate, working DNS and trust in that browser. The container walkthrough remains the first task; exact service-name HTTPS integration has the additional limits described below.

Current support and limitations

Use documentation matching the chosen artifact. npm and package-manager scaffolds are not offered as available installation paths.

Keep the tools that already work

Koi observes Docker/Podman metadata, exposes discovery through HTTP, serves a local DNS zone and exports monitoring targets. Existing resolvers and proxies can remain in place. Each integration has configuration and compatibility requirements; the practical test is whether it removes work from your setup.

The project focuses on Windows with Docker Desktop and Linux with Docker Engine. See the current support page before choosing a version for your setup.

Trusted service names are a separate extension

Koi includes private-CA and TLS primitives. A usable HTTPS URL still needs a matching certificate, correct DNS and trust in the intended client. Container certificate labels do not complete that setup; the current public exact-name grant and ACME integration need further wiring.
