## Plan / exact owner and changed files

it already builds the six supported targets and exercises manifest/npm consumers
without entering tag-gated publication jobs. R28 will strengthen that path instead
of creating a parallel artifact pipeline.

- `.github/workflows/ci.yml` — run exact-tree checks for `dev` and PRs; retain the
  existing Rust, formatting, MSRV, architecture/lean and supply-chain gates while
  making client, launcher, manifest, version and current dashboard coverage visible.
- `.github/workflows/release.yml` — make validation read-only by default, run the
  shared contract checks, retain write permission only on tag-only publishing jobs,
  preserve the six-target build, and emit a candidate validation summary artifact.
- `.github/workflows/publish.yml` — remove independent manual publication and make
  the reusable publishing workflow read-only except for its explicit registry secret.

## Before -> after

Before: `dev` can be untested by hosted CI, manual candidate validation has broad
default permission and no durable joined verdict, and required user-facing contracts
are split across optional commands.

After (planned): pushes and PRs identify their exact checked SHA; ordinary CI runs
the actual contract surfaces; a manual candidate build emits one deterministic JSON
summary joining its source, artifact manifest, hosted run and explicitly pending
native evidence; any missing/skipped/failed required hosted job rejects the hosted
verdict; only a tag path can reach explicitly permissioned publishing jobs.
