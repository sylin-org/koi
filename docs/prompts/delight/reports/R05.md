## Implementation

- `koi-common::service` owns schema-1 catalog/preference DTOs, stable service and
  recognizer/source candidate keys, optimistic command bodies, preference status and
  typed recovery/conflict errors. Unknown newer top-level schemas fail decoding.
- New `koi-preferences` is the sole owner of `state/preferences.json`. It opens status
  before commands, serializes updates, suppresses semantic no-ops, commits via flushed
  temp file plus atomic replacement, publishes status before its event, and returns the
  current revision on conflict. Schema 0 is backed up byte-for-byte to
  `preferences.schema0.json.bak`; malformed and future storage remains visible in
  read-only recovery status and cannot be overwritten.
- `ServiceCatalogRuntime` joins preference status into its one projection. Stable IDs
  carry favorites and aliases; absent favorites retain bounded safe context and become
  honest `absent` services; a same-named different ID cannot inherit intent. Candidate
  dismissal requires its exact detector/source key.
- `koi-serve` mounts `GET /v1/catalog`, `GET /v1/catalog/events`,
  `GET /v1/preferences`, and the two preference `PUT` routes. Catalog snapshot reads
  are loopback-open and remote-DAT-gated; catalog SSE requires DAT everywhere;
  preference reads and writes require DAT plus a loopback/local operator.
- `koi-client` provides schema-checking snapshot/preference commands and a
  `CatalogSubscription` that refetches after a new epoch, revision gap, decode error or
  stream loss. Stale revision and unsupported schema remain typed client errors.
- Koi Desktop now uses the daemon catalog/preference routes through authenticated local
  control. Stable `service:<id>` favorites exist only in its in-memory feed. Legacy
  `koi-watched` migration accepts only exact unique raw observation-name matches, writes
  a byte-exact backup before the first daemon commit, retains unmatched/ambiguous values,
  and leaves the source untouched when any commit fails. Mixed old/new daemon errors are
  explicit `unsupported_schema`, and ambiguous rows cannot be starred.
