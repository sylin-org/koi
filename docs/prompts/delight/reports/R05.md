# R05 report — catalog API and durable personal preferences

Status: **in progress / claimed by windows**

## Task and selected slice

Expose the authoritative service catalog as a typed snapshot plus subscription and
add one durable personal-preferences owner for favorites, friendly aliases and
dismissed local-service suggestions. Join those preferences into the catalog,
preserve absent favorites by stable identity, migrate only unambiguous desktop
`koi-watched` values, and enforce the local-operator plus DAT mutation boundary.

## Architectural guardrails

- `koi-preferences` alone reads or writes `state/preferences.json`; composition
  consumes its typed status and never its repository.
- Existing `CatalogSnapshot`, stable catalog IDs, `StatusFeed`, atomic persistence,
  DAT, local-control and SSE utilities are reused. `PREFERENCES_SCHEMA` and its DTOs
  are new; no existing preference owner or constant duplicates them.
- Constants stay beside their use. New wire types receive serde/schema tests.
- No `mdns-sd` import, global bus, raw discovery cache, Pond preference field,
  alternate IPC protocol, or display-name identity binding is introduced.
- Desktop localStorage is a migration source only. A backup precedes daemon
  commits; ambiguous/unmatched legacy values remain for manual review.
