## Exploration / existing pattern

- `windows_dnsapi.rs::open_dnsapi_browse` walks the complete
  `DNS_QUERY_RESULT` list and forwards every PTR even though it reads each record
  owner. Legal additional service-to-instance PTRs are therefore mislabeled as
  meta-query results and each false type starts another dashboard browse worker.
- `windows_bonjour.rs` is the existing adapter pattern for decoding DNS-SD
  presentation escapes while keeping native values local.
- `DiscoveryHub` already owns canonical keys, one browse per type, cache truth,
  provider-loss retention, route readmission, and status-before-event ordering.
- `MdnsControlPlane::browse` already fences events by route generation; provenance
  will travel through that same owned browse rather than a second status lookup.
- `ServiceType` remains the shared normalization owner. A separate browse parser
  will accept `_subtype._sub._service._tcp.local.` without permitting subtype
  registration or using an allowlist/underscore regex.

The minimized portable fixture will contain one requested meta PTR, an additional
ordinary PTR, SRV, TXT, A and AAAA records, plus mixed-case/trailing-dot variants.
Companion cases cover an ordinary unrelated PTR owner, a subtype query whose target
is the base service instance, escaped dots/backslashes/decimal escapes, duplicates,
and TTL-zero withdrawal.
