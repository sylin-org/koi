## Before -> after

- Before: the Windows callback walked every record in `DNS_QUERY_RESULT` and
  forwarded every PTR, even when `pName` was not the requested browse owner.
  Legal additional service-instance/host records therefore became false
  meta-query types and spawned more dashboard type browses.
- After: classification first compares record owner and requested query with
  ASCII case-insensitive, trailing-dot-insensitive DNS semantics. A meta browse
  accepts only valid base service types; ordinary/subtype browses accept only
  matching owners and derive the base instance namespace from the PTR target.
- Before: instance parsing split on ordinary dots/`._`, losing escaped label
  boundaries; subtype resync compared selector text with base record type.
- After: escaped dots, backslashes and decimal escapes are decoded at the shared
  provider boundary; subtype query identity is retained separately from the base
  record type and all consumers resync from that identity.
- Before: the snapshot could not distinguish an empty demanded browse from an
  unavailable source, and facts lacked concrete provider/generation provenance.
- After: `sources` reports every demanded query even when empty/unrouted;
  `observations` carries query/provider/generation/availability beside accepted
  facts. Compatibility `service_types`/`records` remain additive and deduplicated.
