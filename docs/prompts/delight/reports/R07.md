## Browser authorization implementation — 2026-09-06

The operator approved ADR + implementation after replacing manual DAT entry with
local opening and one-use QR invitations. [ADR-046](../../../adr/046-browser-invitations-and-sessions.md)
is accepted design. Private phone pairing requires browser access, the phone option
and a usable CertMesh identity; loopback opening works without CertMesh, and public
Pond remains separately armed. Loss of private identity never downgrades to HTTP.

The implementation uses the existing CertMesh TLS identity bridge/resolver, atomic
persistence, shared Rust Home renderer, refresh scheduler, local operator discovery
and native external opener. New exact owners/files are recorded in the
[contract](../CONTRACT.md#r07-browser-access-extension--adr-046-2026-09-06).
The optional HTTPS listener uses operator port + 4, closes owned connections on
identity loss, checks firewall readiness and never changes host firewall rules.
It mounts no operator/MCP routes. Browser grants authorize service views only.

The browser generates a non-extractable P-256 key and signs one-use challenges.
Only public session metadata is persisted by the daemon; no DAT enters a page.
Temporary/remembered browser pointers are separated; key storage is checked before
redemption, expired keys are pruned, and disconnect is durable. New wire values and
CLI help/OpenAPI/reference docs accompany the implementation. Native controls use
shared presentation, the typed local client, SVG QR rendering and authoritative
status observation, with bounded exact local protocol routes.

Focused evidence so far: ten selected serving tests passed (including the existing
Pond browser test); invitation concurrency/expiry, method/query/key/replay scope,
wrong origin, DAT + actual loopback, atomic persistence failure, future schema,
revocation/restart, identity loss/trust-anchor replacement and joined TLS teardown
are covered. An isolated Chromium process against the actual Rust router passed
preview, Connect, non-extractable remembered key, search/reload/return, automatic
local connection, temporary-tab isolation and disconnect/cleanup. This is isolated
source integration, not installed or physical phone acceptance. Common wire, client
schema/path and shared UI escaping/readiness tests passed. All eight CLI help/conformance tests and focused strict Clippy passed. Native
code compiled against temporary local overrides and its new route guard passed;
