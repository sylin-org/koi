**Reusing / pattern:** CatalogSnapshot/Service/Endpoint and stable ServiceId,
existing pure koi-ui components and URL parser, existing platform launch mechanisms.
Search matches all query words across name/alias, exact associated device names/
addresses, endpoint host and category. Ordering uses stable IDs; selection is by ID,
not current row position; absent favorites remain catalog-owned. Attention is
bounded, with a total count instead of an unbounded feed.

**Risks / guards:** Only explicit Open + browser-usable HTTP(S) evidence can yield
a destination. API-only/absent/stale/ambiguous services, wildcard hosts, credentials,
control characters, backslashes, host/path confusion and unsafe schemes fail closed.

not proof of reachability or client TLS trust. Windows uses ShellExecuteW with a
URL as lpFile and no command parameters, never cmd/start. Tests use a launch seam,
not the real user browser. No mdns-sd import, domain duplication, upward dependency,
new protocol schema or centralized constants. The charter supersedes the old
explore plan-approval pause under the user's proceed instruction.
