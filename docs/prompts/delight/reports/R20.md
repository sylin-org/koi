# R20 — authorized service certificates

Status: implemented / pending hosted CI. The source acceptance cases pass on
Windows; R21/R22 retain the full Proxy/client outcome.

## Task and selected slice

Give one catalog service an explicit configured-zone name grant and let either the
host TLS termination owner or one named ACME account obtain and renew a leaf whose
SAN is exactly that grant. Reject ungranted names, multi-name orders, and wildcards.

## Before -> after

- Before: any ACME account could order any in-zone name, including a wildcard;
  successful issuance created/updated a Certmesh member. There was no durable
  service-name authorization or host service-leaf lifecycle.
- After: a normalized non-apex configured-zone name is uniquely bound to one stable
  service and `HostProxy` or one persisted ACME account. Identical grants are
  idempotent; a different service/owner conflicts instead of silently transferring.
- Host issuance creates one-SAN material under
  `certs/services/<dns-name>/{cert.pem,key.pem,ca.pem,fullchain.pem}`. The four
  files, public status, and audit entry commit as one recoverable generation.
  Renewal rotates the key; a signing/commit failure leaves the prior usable bytes.
  Reuse validates the leaf SAN, key, CA, full chain, fingerprint, expiry, and
  renewal threshold.
- ACME orders contain exactly one granted name. Finalization rechecks that exact
  account grant inside the signing transition, closes a revoke/ready-order race,
  uses the roster leaf-lifetime policy, and records actual leaf expiry.
- Revocation removes the exact grant and host-owned material. Koi-aware issuance
  rejects it immediately. Ordinary TLS clients still lack CRL/OCSP and can accept
  a copied leaf until its real `NotAfter`.

## Positive and negative acceptance results

- Actual host and ACME leaves contain exactly the granted SAN and chain to the CA.
- Wrong service IDs, wrong ACME accounts, name conflicts, zone apex, IPs,
  out-of-zone names, wildcard names, multi-name orders, and CSR SAN expansion fail.
- A grant revoked after challenge validation cannot be finalized.
- Renewal preserves the exact name, rotates the key, and atomically replaces all
  consumer files. Injected commit failure preserves the prior material; a missing
  chain file triggers a complete replacement generation rather than false reuse.
- Old roster JSON without `service_name_grants` loads with an empty set; grant
  round trips reject future schema. Cancellation-after-durable-commit converges
  grant, ACME order, and event without retry.
- `ServiceCertificate` has redacted `Debug`, cannot serialize, and public events,
  roster/audit/status adapters contain no private key or certificate PEM.
