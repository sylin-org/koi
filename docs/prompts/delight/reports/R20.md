Status: in_progress / pending. This is the published implementation claim, not

## Task and selected slice

Give one catalog service an explicit configured-zone name grant and let the host
TLS termination owner or one named ACME account obtain and renew a leaf whose SAN
is exactly that grant. Reject ungranted names and every wildcard.

## Exploration / exact owner and changed files

**Task:** extend the CertMesh business/domain layer and its ACME adapter with an
exact, durable service-name authorization and host-custodied certificate lifecycle.

**Files read:** `issuance_names.rs` owns configured-zone SAN normalization;
`core_enroll.rs` and `core_renewal.rs` demonstrate atomic leaf replacement and
reload-safe failure behavior; `roster.rs` is the durable CA aggregate;
`acme/state.rs`, `acme/router.rs`, and `acme/order.rs` own account/order/finalize
authorization; `principal.rs` demonstrates named caller rejection; `ca.rs` owns
leaf signing; `koi-dns/aliases.rs` owns DNS aliases but not certificate grants;
ADR-027 and ADR-044 fix short-leaf and host-termination policy.

**Reusing:** `ServiceId`, `IssuanceNames`, `CertPolicy`, `ca::issue_certificate`,
the CertMesh roster/repository transaction boundary, ACME account thumbprints and
order ownership, and Proxy's existing hot-reloadable certificate input. No service
grant type, durable grant collection, or exact service-leaf facade exists.

**Pattern:** follow `core_enroll.rs::self_enroll_under_transition` and
`core_renewal.rs` for prepare -> atomic artifact commit -> in-memory publication ->
secret-free event ordering; ACME repeats authorization inside finalization to close
grant-revocation races.

**Risks:** old ACME behavior intentionally allowed arbitrary in-zone wildcards, so
the existing conformance fixture must create an account-bound exact grant first.
The R21 coordinator and Proxy per-service input do not exist yet; R20 exposes typed
in-process certificate material but does not invent R21's operation, listener or
HTTP routes. Ordinary TLS clients may continue accepting a copied revoked leaf until
its actual expiry because CertMesh supplies no CRL/OCSP.

No new `mdns-sd` import, global constant, duplicate protocol/core type, HTTP route,
manifest/lockfile or sibling-repository write is planned. New serializable grant
types receive round-trip/migration tests; key-bearing material is deliberately not
serializable and has redacted `Debug`.
